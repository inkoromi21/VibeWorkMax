# Выборка VibeWork для переноса

Эта папка содержит только те части старого VibeWork, которые нужны при создании проекта MAX. Она подготовлена, чтобы Codex не индексировал весь старый репозиторий при выполнении каждого промта.

## Как использовать

1. Сначала открыть `SOURCE_MANIFEST.md` и выбрать только группу, относящуюся к текущей задаче.
2. Читать файлы из этой папки как справочный материал, а не как готовый runtime нового продукта.
3. Переносить правила, алгоритмы, тестовые случаи и структуры данных. Python-код переводить на целевой TypeScript-стек там, где этого требует архитектура.
4. Не сохранять старые импорты, SQLite, FastAPI-маршруты, старый LLM-клиент и глобальное состояние.
5. После переноса добавлять provenance в новый код или документацию: исходный файл, что было перенесено и что изменено.

- `.env`, ключи, токены и конфигурация с секретами;
- `vibework.db` и любые пользовательские данные;

- файлы запуска и деплоя, не соответствующие целевому стеку.
