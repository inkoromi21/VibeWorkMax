# Перенос правил VibeWork в MAX-бота

| Подготовленный источник          | Что использовано                                     | Изменение в MAX                                                                                                           |
| -------------------------------- | ---------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| `services/user_pain_mapping.py`  | только ключевые слова как детерминированный fallback | восемь legacy «болей» сведены к четырём нормативным типам 4.0; неоднозначность не классифицируется случайно               |
| `services/diagnostics.py`        | принцип частичного результата при неполных данных    | ответ «не знаю» и пропуск сохраняются как отдельные состояния, а не как ошибка                                            |
| `services/assessment_routing.py` | идея адаптивного выбора следующего шага              | фиксированные карьерные треки не перенесены: бот начинает со свободно сформулированной проблемы                           |
| `services/learning/progress.py`  | восстановление позиции                               | состояние шага и попытка хранятся отдельно и имеют idempotency key                                                        |
| `services/simulator_progress.py` | устойчивое сохранение последней позиции              | SQLite и полный raw state не перенесены; PostgreSQL хранит только versioned шаг, позицию и идемпотентные события открытия |

Legacy Python, SQLite, токены, пользовательские данные и runtime не импортируются.
